# Vocabulary guard — word list.
#
# Design section 16, altitude rule: no type of the kernel names a domain
# entity, a transport or a technology. `ci/check_vocabulary.py` turns that
# sentence into a build failure over `crates/**/*.rs` and `crates/**/Cargo.toml`.
#
# Two sections, because the two kinds of word need different reach:
#
#   [anywhere]     matched over the whole file, comments and string literals
#                  included. Only names a generic kernel never needs to write,
#                  not even to say it does not do them.
#   [identifiers]  matched over code only — comments, string literals and
#                  character literals are blanked out first. For words ordinary
#                  prose uses freely ("it opens no socket", "the arithmetic
#                  product") but which must never name a type, a field, a
#                  function, a module or a feature.
#
# Matching is case insensitive and token bounded, a case change counting as a
# boundary: `http` catches `HttpThing`, `http_thing` and `myHttpThing`, and does
# not catch `https` or `restart`. A plural needs its own entry.
#
# The list is meant to grow. When an application uses this kernel, its own
# domain glossary belongs in the [identifiers] section: that is the guard the
# design asks for ("grep en CI sur un glossaire de domaine du projet").
# Entries are one alphanumeric token per line; `#` starts a comment.
#
# Deliberately absent, because the kernel's own lifecycle vocabulary owns them:
# `order` (boot order), `rollback` (boot rollback), `controller`
# (`ShutdownController`), `payload` (event payload), `transaction`. Adding one
# of them would flag the kernel's own mechanism, not a domain leak.
